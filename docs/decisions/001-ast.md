# 001: AST library for edit ops

**Status:** accepted · 2026-09-29 · T0.2

## Context

Every edit Skeleton makes to a user project has to be a minimal patch that keeps
formatting, comments and TypeScript syntax untouched outside the target node
(CLAUDE.md non-negotiables 2 and 3). T0.2 asks for the same edit (insert a JSX
child at an index) built with Babel + recast and with ts-morph, compared on
formatting/comment preservation, TS syntax survival and diff size.

## Spike

The input was a page with deliberately awkward agent code: a generic hook
(`useList<T extends { id: string }>`) with odd spacing and a trailing comment, JSX
comments between children, single-quoted attributes, an inline handler and a
`.map()` expression.

| Approach | Insert diff | Notes |
|---|---|---|
| `@babel/parser` + `recast` (AST splice, `recast.print`) | +1 line | Untouched nodes reprinted verbatim from the original source, generics and comments intact |
| ts-morph structural API (`setBodyText`) | +8 / −7 lines | Re-indents every sibling in the parent and the closing tag. Fails "touch only the target" |
| ts-morph `insertText` at a node position | +1 line | Minimal, but this is plain text splicing: ts-morph only supplies the offset and re-parses the whole file after each edit |

I also ran recast through the other op shapes:

- **move** of a `{rows.map(...)}` block: moved verbatim; the diff is just the removed and added lines
- **attribute change:** one line changed. Recast normalises that one attribute's quotes (`'outline'` → `"ghost"`), and nothing else on the line changes
- **className change:** one line
- **remove:** one line

The only artefact was a leftover blank line after a move. It came from the spike
not removing the whitespace `JSXText` next to the moved node, not from recast.

## Decision

Use **`@babel/parser` (TypeScript + JSX plugins) with `recast`** for all parsing and
edit ops in `core`.

## Consequences

- Edit ops mutate the recast AST and call `recast.print`. Only modified nodes get
  reprinted, so diffs stay local.
- Ops own whitespace `JSXText` handling (indentation of inserted children,
  removing the separator next to a moved or removed child). Tests cover it.
- A changed attribute is reprinted with double quotes. That's acceptable because it
  sits on the target node, which the op is allowed to change.
- Prettier is **not** run inside `core` ops. Prettier's range formatting widens to
  the enclosing statement, which in a page component is the whole `return (...)`
  and would reformat agent code. Recast's output for changed nodes is already
  formatted to match its surroundings. We'll revisit this in T3.7 (post-edit
  pipeline).
- ts-morph stays out of the dependency tree. If we ever need type information (e.g.
  prop schemas from `.d.ts`), that's a separate decision.
